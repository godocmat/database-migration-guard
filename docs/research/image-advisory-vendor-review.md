Both Noble images have Canonical's Expat-side backport for CVE-2026-41080. The shipped `libexpat.so.1` exports `XML_SetHashSalt16Bytes`. The shipped `/usr/bin/python3.12` contains the built-in `pyexpat` module and imports `XML_SetHashSalt` only. This confirms the missing Python-side change for CVE-2026-7210 on these image bytes. [Canonical Expat backport](https://ubuntu.com/security/CVE-2026-41080) · [CPython maintainer issue](https://github.com/python/cpython/issues/149018)

The CLI starts the Rust executable as UID/GID 65532. The GitLab gate uses Python for orchestration, TOML and JSON, reads candidate files as Git blobs, and invokes native Git for HTTPS. The reviewed entrypoints do not invoke Python tar extraction, XML parsers, Python TLS, or the util-linux mount path. PostgreSQL inspection uses Rustls with the CA explicitly supplied to the command. Both Ubuntu filesystems contain the setuid util-linux `/usr/bin/mount` (mode 4755), libmount, and an `/etc/fstab` without configured entries. The GitLab image defaults to root, and the documented runner profile calls for an isolated, unprivileged executor. Local replay used a nonroot UID with capabilities dropped. Hosted runner settings remain a separate verification item. [CLI image](../../integrations/cli/Containerfile) · [GitLab gate](../../integrations/gitlab/gate.py) · [Runner profile](../gitlab-ci.md) · [PostgreSQL TLS](../../crates/dmg-inspect/src/transport.rs)

Both original images have `ca-certificates` `20260816ubuntu0.24.04.2`, newer than Canonical's Noble eMudhra trust-store update `20260816ubuntu0.24.04.1`. Their identical system CA bundle, SHA-256 `64e7c24b0536b525fb19b145768bd5e6e12ced0df3db837c34553ea789acd143`, excludes the emSign ECC Root CA - G3 and Comodo AAA Certificate Services roots Canonical identified. The Git HTTPS helper links to GnuTLS libcurl and the gate uses its default system trust. This verifies the trust-store mitigation for that path. The Python-level denylist remains unresolved in the Noble package record. [Canonical trust-store notice](https://ubuntu.com/security/notices/USN-8944-1) · [Canonical incident details](https://ubuntu.com/blog/emudhra-ca-compromise-fixes-available) · [Python 3.12.16 changelog](https://docs.python.org/3.12/whatsnew/changelog.html#python-3-12-16-final)

## Wolfi runtime candidate

The preliminary Wolfi Git package closure `sha256:aee2616b69f3a8861a5384edab3565060aa4ee6af0eeca1bfeb5fd9a89bf6735` has no Python. The preliminary Python closure `sha256:7c0860125d3cb652cc42987326c167c49eddc274ae9c014d03f8fdd3e97e43a2` contains `python-3.15`, `python-3.15-base`, and `python-3.15-runtime` at `3.15.2_git20261106-r0`, and `libexpat1` at `2.10.0-r1`. Its build uses system Expat and pins CPython commit `4af98bdb94beb37453a33b989f8ef466f8ef0e21`, a descendant of the 3.15.2 release tag. Wolfi's advisory feed records the eMudhra denylist fix from `3.15.2_git20261030-r0`. The package-closure image has the Python Expat extension's import and the shared libexpat's definition of `XML_SetHashSalt16Bytes`. The ElementTree extension obtains the same API through the Python Expat extension.
