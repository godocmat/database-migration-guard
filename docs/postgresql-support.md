# PostgreSQL parser support

Guard uses `pg_query` 18.1.0 and its PostgreSQL 18.6 grammar for target majors 17 and 18. It parses the exact original UTF-8 migration bytes, checks them against discovery’s SHA-256, and reports zero-based half-open byte ranges with one-based lines and Unicode scalar columns. Statement ranges omit delimiters and leading or trailing comments. Multi-action `ALTER TABLE` and `RENAME` have source locations for their individual operations. [Parser and server conformance evidence](../spikes/dmg-01-parser/README.md)

| Supported operation | Offline facts |
| --- | --- |
| `CREATE SCHEMA`, `CREATE TABLE` | Name, existence condition, ordinary and partitioned table kind, partition parent, supported columns and constraints. |
| `ALTER TABLE` | Supported column additions and removals, defaults, type changes and `USING` presence, nullability changes, constraint additions and removals, and constraint validation. |
| Rename, drop, truncate | Table, column, index, and table-constraint rename. Supported drop object identities, concurrent index-drop flag, and truncate relation names and options. |
| `CREATE INDEX` | Target, name, simple column keys, uniqueness, concurrent mode, existence condition, and predicate presence. |
| `UPDATE`, `DELETE`, `INSERT` | Target, absent or simple predicates and provable constant booleans for updates and deletes, and simple inserts. |
| Transaction statements and simple `SELECT` | `BEGIN` or `START`, `COMMIT`, `ROLLBACK`, savepoints, and literal selects. Each operation keeps its runner segment, transaction wrapper, and statement-delivery context. |

Column-add facts distinguish absent, constant, stable, volatile, and unknown defaults. The recognized function and cast set assumes ordinary PostgreSQL built-in resolution for unqualified names. Custom defaults and casts can need schema evidence. Check constraints retain direct `IS NOT NULL` proofs, validation state, enforcement, and `NO INHERIT`. The rule engine combines those facts with the ordered migration context. [Function volatility](https://www.postgresql.org/docs/18/xfunc-volatility.html) · [PostgreSQL name resolution](https://www.postgresql.org/docs/18/runtime-config-client.html#GUC-SEARCH-PATH)

On PostgreSQL 17, the parser reports unsupported PostgreSQL 18 constraint forms, including deferred-validation `NOT NULL`, `NOT ENFORCED`, and `NOT VALID` foreign keys on known partitioned parents. A PostgreSQL 17 `NOT VALID` foreign key with unresolved target kind gets an explicit coverage gap. Both majors report a compatibility gap for `CREATE INDEX CONCURRENTLY` on a known partitioned parent. Conditional creation or uncertain transaction or schema history can leave the relation kind unresolved. [PostgreSQL 18 constraint changes](https://www.postgresql.org/docs/18/release-18.html#RELEASE-18-CONSTRAINTS) · [PostgreSQL 17 concurrent indexes](https://www.postgresql.org/docs/17/sql-createindex.html#SQL-CREATEINDEX-CONCURRENTLY) · [PostgreSQL 18 concurrent indexes](https://www.postgresql.org/docs/18/sql-createindex.html#SQL-CREATEINDEX-CONCURRENTLY)

Analysis records incomplete coverage for unsupported constructs such as procedural SQL, client directives, unresolved templates, unsupported DML expressions or clauses, and ambiguous source alignment. It can preserve independently delimited statements after a grammar error, or a valid prefix before a client directive or template. An ambiguous or lexically invalid segment can prevent statement recovery. `DO` bodies are identified at their literal span when available. Failure diagnostics use generic messages at statement or segment precision through the pinned public binding.

The parser bounds an original file at 8 MiB, each adapter-delivered segment at 256 KiB and 32,768 tokens, delimiter nesting at 64, and a segment at 2,048 top-level statement delimiters. It processes at most 1,024 segments per file. Discovery can impose lower limits. Exceeding a limit produces an incomplete coverage diagnostic. The native binding temporarily redirects process-wide standard error, so this crate serializes native scanner and parser calls.
