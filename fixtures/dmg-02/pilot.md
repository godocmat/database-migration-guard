# Squawk and Atlas pilot protocol

Use the reviewed [competitor research](../../docs/research/fixtures-and-competitors.md#squawk-and-atlas-pilot) and the DMG-02 development cases. The pilot chooses the tool pins and records available features and editions before scoring.

1. **Freeze comparable inputs.** Record each tool version, binary SHA-256, edition and account prerequisites, configuration and ruleset, CI action commits, PostgreSQL minor and image digest, host, and native runner settings. Start with R01, R03, R05, and R07 in a shared forward-only directory with equal-width numeric versions. Use the same selected SQL bytes and target, and replay the same baseline schema where a tool supports replay. Verify selected paths, order, and transaction semantics before including a run in the shared score. Keep a path and digest mapping for adapted inputs and record the applicability of each result.
2. **Run lint and the merge check.** Start with tool defaults plus input settings. Feed Squawk the selected forward paths, target major, applicable transaction-wrapper setting, and JSON reporter. Attribute Git selection performed by the harness to the harness. For Atlas, use a disposable dev database, a local ref to the fixed base with `--git-base`, and confirm the paths selected by `--latest` for an append-only run. Compare R05 using Squawk's `require-concurrent-index-creation` and Atlas's `concurrent_index`. Freeze matched settings before the matched-policy pass and retain both passes. Run a passing PR, a risky PR, and its corrected revision through the available GitHub integrations. Compare exception edit scope, rationale, approval path, and review time with a dedicated exception case. [Squawk CLI](https://squawkhq.com/docs/cli) · [Squawk GitHub integration](https://squawkhq.com/docs/github_app) · [Atlas lint](https://atlasgo.io/versioned/lint) · [Atlas CI](https://atlasgo.io/versioned/setup-cicd)
3. **Probe selection and integrity.** Confirm Up-only selection in Atlas's candidate `golang-migrate` format before scoring reversible SQLx files. Exercise G02 and G03 with the original `atlas.sum` and a regenerated candidate sum. Record which input proves each integrity claim. Score T cases only where the pinned tools represent the same execution behavior with the original bytes. Atlas's concurrency analyzer recognizes its own `atlas:txmode none` directive, so a changed directive needs an adaptation record and a distinct result. [Atlas analyzers](https://atlasgo.io/lint/analyzers) · [Directory integrity](https://atlasgo.io/concepts/migration-directory-integrity) · [Formats](https://atlasgo.io/versioned/diff#supported-formats)
4. **Run the seeded rehearsal.** Use R04c with both seeds. In Atlas `migrate test`, apply version 1, seed the rows, install the unvalidated CHECK, then apply the candidate validation. Assert `pg_constraint.convalidated` and row preservation in the clean run and capture the validation error with a null. Use the same sequence and assertions for the native runner oracle in the [recorded probes](evidence/README.md). Verify available Atlas commands and analyzers for the pinned edition and record Community and Pro independently if both are available. Guard rehearsal belongs to DMG-12. Attribute each finding and rehearsal result to the command that produced it. [Atlas dev database](https://atlasgo.io/concepts/dev-database) · [Migration tests](https://atlasgo.io/testing/migrate) · [Atlas edition change](https://atlasgo.io/blog/2025/10/28/v038-analyzers-pii-and-migration-hooks)
5. **Score by risk and scope.** Match findings to the reviewed risk, object, and statement before comparing severity or exit codes. For each major, count hits, false positives, and missed risks on supported shared cases. Count skipped, unsupported, and incomplete runs with reasons against the full planned scope. Record location precision, whether reviewers could confirm the risk and choose a correction, time to first passing CI check, setup and recurring prerequisites, and active reviewer time. Rotate tool order among reviewers and repeat runs under recorded cache and startup conditions. Retain tool output, configuration, and setup, scan, and rehearsal timings.

Record one row per pinned tool, case, major, and policy pass.
